# EcoFFT

EcoFFT — компонент прямого и обратного быстрого преобразования Фурье для Eco ACOM. Он обрабатывает комплексные сигналы длиной от 1 до 65 536 отсчетов, включая длины, не равные степени двойки. Доступны два алгоритма: DIT и DIF; для произвольной длины используется алгоритм Блюстейна.

Компонент предоставляет сервисный API, объектный план с собственным состоянием, векторы, матрицы и фильтр циклической свертки. Консольная программа `eco_fft` вычисляет FFT/IFFT для пользовательских CSV-файлов. Вычислительное ядро написано на C11 и не зависит от libc, libm или сторонней FFT-библиотеки.

## Сборка

Основной способ — Docker с Linux-контейнерами. В Windows подходит Docker Desktop. Команды выполняются из корня проекта; устанавливать компилятор, Python и Eco.AI в Windows не требуется.

```powershell
docker compose build
docker compose run --rm fft
```

Первой команде нужен интернет для загрузки базового образа и инструментов. Сборка исходников и последующие запуски выполняются без сети. Eco SDK уже находится в `vendor/eco`.

Результат сборки:

| Файл | Назначение |
| --- | --- |
| `bin/eco_fft` | Консольная программа для Linux x86_64 |
| `bin/C345FB78707144109821A6EF25310070.so` | Динамический компонент DIT |
| `bin/C345FB78707144109821A6EF25310071.so` | Динамический компонент DIF |
| `lib/libC345FB78707144109821A6EF25310070.a` | Статическая библиотека DIT |
| `lib/libC345FB78707144109821A6EF25310071.a` | Статическая библиотека DIF |

Готовые файлы также включены в проект. Это Linux-бинарники; в Windows они запускаются через Docker. Промежуточные файлы CMake создаются в `build/`.

## Использование

Входной файл содержит два столбца: действительную и мнимую части каждого отсчета. Заголовок `real,imag` необязателен. Разделитель — запятая, десятичный разделитель — точка.

```csv
real,imag
1,0
2,0
3,0
4,0
```

Поддерживаются UTF-8, необязательный BOM, окончания строк LF/CRLF, пустые строки и строки комментариев, начинающиеся с `#`. Каждая строка данных содержит ровно два числа. Размер сигнала определяется числом строк. Части входных значений должны быть конечными и по модулю не превышать `1e100`. В объектном режиме этот предел действует и на сохраняемый результат; превышение возвращает ошибку. Для последовательных FFT/IFFT выбирайте амплитуды, при которых спектр также укладывается во входной диапазон.

Прямое преобразование готового примера:

```powershell
docker compose run --rm fft bin/eco_fft --fft --input=examples/signal.csv --output=build/spectrum.csv
```

Обратное преобразование через объектный план и алгоритм DIF:

```powershell
docker compose run --rm fft bin/eco_fft --ifft --input=build/spectrum.csv --output=build/restored.csv --algorithm=dif --architecture=object
```

Файлы `build/spectrum.csv` и `build/restored.csv` появляются в этой же папке проекта на компьютере. Пользовательские входные файлы следует помещать внутрь проекта; пути в команде задаются относительно его корня. Для пути с пробелами заключите весь аргумент в кавычки: `"--input=data/my signal.csv"`.

Проверка загрузки динамической библиотеки:

```powershell
docker compose run --rm fft bin/eco_fft --fft --input=examples/complex.csv --algorithm=dif --dynamic=bin
```

Без `--output` результат выводится в стандартный вывод в том же CSV-формате. `--input=-` читает стандартный ввод; `--output=-` явно выбирает стандартный вывод. Для конвейеров Docker Compose используйте `-T`:

```powershell
Get-Content examples/signal.csv | docker compose run --rm -T fft bin/eco_fft --fft --input=-
```

| Параметр | Значения и поведение |
| --- | --- |
| Операция | `--fft` или `--ifft` |
| `--input` | Обязательный путь к CSV либо `-` |
| `--output` | Путь к результату либо `-`; по умолчанию стандартный вывод |
| `--algorithm` | `dit` по умолчанию или `dif` |
| `--architecture` | `service` по умолчанию или `object` |
| `--dynamic` | Каталог `.so`; без параметра используются статически связанные компоненты |
| `--help` | Полная справка |

FFT использует отрицательный знак экспоненты, IFFT — положительный знак и нормировку `1/N`. Частоты идут в обычном порядке, без `fftshift`. Для `[1,2,3,4]` результат равен `[10, -2+2i, -2, -2-2i]`. Небольшие остатки около нуля обусловлены округлением.

При ошибке программа возвращает ненулевой код и пишет диагностику в stderr. Вход читается и преобразуется до открытия выходного файла: ошибка входных данных не создает и не перезаписывает результат. Успешная операция заменяет существующий выходной файл. Сбой записи может оставить частичный файл.

## Подключение из C

Публичный контракт находится в [include/IEcoDSP.h](include/IEcoDSP.h). Пример [examples/use_component.c](examples/use_component.c) — самостоятельное Eco-приложение с регистрацией фабрик, запросом `IEcoDSP`, FFT/IFFT и освобождением интерфейсов. Он собирается вместе с проектом:

```powershell
docker compose run --rm fft build/release/eco_fft_example
```

После получения `IEcoDSP* dsp` сервисный вызов выглядит так:

```c
EcoComplexD x[4] = {{1, 0}, {2, 0}, {3, 0}, {4, 0}};
EcoComplexD spectrum[4];
int16_t status = dsp->pVTbl->fft(dsp, 4, x, spectrum);
/* status == ECO_OK: spectrum contains the result. */
```

Для повторных преобразований одного размера используйте `CreatePlan → Load → FFT/IFFT → Store`. План хранит копию сигнала и подготовленные таблицы. Каждый интерфейс, полученный через успешный `Create*` или `QueryInterface`, требует `Release`. Вызовы к одному объекту нужно синхронизировать на стороне клиента.

`fftf/ifftf`, `fft/ifft` и `fftl/ifftl` работают с комплексными `float`, `double` и `long double`. `ffti/iffti` и `fftlong/ifftlong` принимают действительные целые значения и возвращают комплексные `double`. Идентификаторы интерфейсов и компонентов закреплены в заголовке.

`IEcoMatrix` предоставляет хранение элементов, а не двумерное FFT. `IEcoDigitalFilter` вычисляет N-точечную циклическую свертку и сохраняет спектр ядра между вызовами.

## Проверка и измерения

```powershell
docker compose run --rm fft bash scripts/verify.sh
```

Проверка включает математические эталоны, ошибки API, управление памятью, загрузку обеих `.so`, пример интеграции, CSV-интерфейс, AddressSanitizer/UndefinedBehaviorSanitizer и аудит отсутствия внешних импортов у компонентов. Журналы и CSV сохраняются в `build/results/`.

Отдельные режимы:

```powershell
docker compose run --rm fft bin/eco_fft --test
docker compose run --rm fft bin/eco_fft --demo
docker compose run --rm fft bin/eco_fft --benchmark
```

Эти режимы запускают оба алгоритма; ограничить выбор можно через `--algorithm=dit` или `--algorithm=dif`. Измерение времени выполняется отдельно от обычной сборки. Режим `--benchmark` использует независимые реализации ДПФ и рекурсивного FFT на `math.h` в клиенте.

Для сравнения со стандартной библиотекой [FFTW](https://www.fftw.org/) предусмотрен отдельный клиент:

```powershell
docker compose run --rm fft bash scripts/compare_fftw.sh
```

Скрипт собирает `build/reference/eco_fft_reference`, выполняет 720 сравнений результатов FFT/IFFT для DIT/DIF, сервисного и объектного API и измеряет время на десяти длинах до 65 536. Обе реализации используют `long double`; обратное преобразование FFTW делится на `N`. Результаты: `build/results/fftw-accuracy.csv`, `fftw-benchmark.csv`, `fftw-comparison.log` и `fftw-environment.json`. Для повторной проверки точности без измерения времени запустите `build/reference/eco_fft_reference --check` в контейнере.

Времена полного вызова и повторного использования плана приведены отдельно. Используются `FFTW_ESTIMATE`, один поток, прогрев, адаптивный размер пакета и медиана семи замеров. Время включает копирование входа/выхода, а для IFFT — нормировку. Внутрипроцессный кэш планировщика FFTW прогрет; это не измерение холодного старта. Подготовка планов также измеряется отдельно. Скорость зависит от процессора и нагрузки; сравнение не определяет предельную производительность FFTW.

FFTW устанавливается только в Docker-образ и связывается только с дополнительным клиентом сравнения. Основной `eco_fft` и библиотеки компонентов собираются без нее. Если образ создан до добавления этого сравнения, сначала повторите `docker compose build`.

## Сборка непосредственно в Linux

Нужны Linux x86_64, GCC с поддержкой C11, CMake ≥ 3.20, Ninja и binutils. Для проверочных скриптов нужен Python 3.10 или новее; сторонние Python-пакеты не требуются.

```bash
bash scripts/build.sh
./bin/eco_fft --fft --input=examples/signal.csv
bash scripts/verify.sh
```

Для необязательного сравнения с FFTW дополнительно нужны заголовок `fftw3.h` и библиотека `fftw3l` (пакет `libfftw3-dev` в Debian/Ubuntu). Затем выполните `bash scripts/compare_fftw.sh`. В CMake этот клиент включается явно параметром `-DECO_FFTW_REFERENCE=ON`; обычная сборка не ищет FFTW.
